## 20. Development roadmap (1 senior full-stack dev plus Claude Code. Halve the calendar with 2 devs)

| Week | Milestone | Done when |
|---|---|---|
| **0** (2 days) | Bootstrap | `create-payload-app` (Next + Postgres template) in the monorepo. shadcn init. Compose up locally. `.mcp.json` + `CLAUDE.md` |
| **1** | Tenancy & admin CRUD | Collections for Tenants/Users/Restaurants/Categories/Dishes/Media. `plugin-multi-tenant`, storage-s3 → SeaweedFS, orderable categories/dishes, RLS migration, **cross-tenant tests green** |
| **2** | Public menu v1 | `/[restaurant]` mobile-first menu: sticky category tabs, dish cards, dish bottom sheet, photos (AVIF/WebP srcset), theme from CSS vars, JSON-LD, ISR + revalidate hooks. Lighthouse mobile ≥ 95 |
| **3** | 3D view + AR (manual GLB) | GLB/USDZ upload → gltf-transform optimise job (CPU, same queue) → model-viewer in the dish sheet → "View On My Table" on Android and iOS. Fallbacks verified on 5 real devices |
| **4** | QR + onboarding | Restaurant/table QR (SVG/PNG/PDF table tents), `?table=` capture, signup wizard, publish flow, Umami + `menu_events` |
| **5–6** | Photogrammetry worker | Worker image, stages 0–7, progress SSE, capture guide, ChArUco scale, 3 golden fixtures in CI (GPU runner or nightly) |
| **7** | AI fallback + hardening | TRELLIS.2 path, quotas/plans, rate limits, CSP, backups + restore drill, Trivy/OSV in CI |
| **8** | **Pilot launch** | 3–5 real restaurants, production on Coolify/Hetzner, uptime monitoring, feedback loop |
| 9–12 | SaaS polish | Custom domains (Caddy on-demand TLS), billing adapters (manual → Stripe/Mercado Pago/regional), i18n ES/EN/PT/GN, analytics dashboard |
| Phase 2 (Q+1) | Modules | Orders (table-signed QR) → WhatsApp Cloud API notifications → payments → reservations (Cal) → loyalty/customers (Better Auth) → franchises (tenant hierarchy) → white label |

**MVP scope cut line:** weeks 0–4 are a sellable product (menus with 3D and AR from uploaded models). Photogrammetry (weeks 5–6) is the differentiator but isn't blocking. You can launch with "we scan your dishes for you" as a service while the self-serve pipeline matures.

## 22. CI/CD pipeline

```
 PR ──► ci.yml ───────────────────────────────────────────────────────────────┐
        pnpm install (cache) → turbo lint typecheck test (Vitest)             │
        → Postgres service container → payload migrate → tenancy.spec (RLS)  │
        → next build → Playwright e2e (iPhone 15 + Pixel 8 viewports)         │
        → Lighthouse CI budget (LCP < 2.0s, JS < 150KB on menu route)         │
        → OSV-Scanner + license check (license-checker: deny GPL/AGPL/BUSL    │
          in apps/ and packages/; allow in workers/ images)                   │
                                                                             │
 main ─► release.yml                                                         │
        build web image (Docker buildx, cache) → Trivy scan → SBOM (Syft)    │
        → push ghcr.io/…/menu3d-web:{sha,latest}                             │
        → payload migrate (job container against staging)                    │
        → deploy staging (Coolify webhook) → smoke tests                     │
        → manual approval (environment: production) → deploy prod webhook    │
                                                                             │
 workers/** ─► worker.yml                                                    │
        build CUDA image (weekly + on change; large, cached layers)          │
        → run golden-fixture reconstruction on self-hosted GPU runner        │
          (assert: tris ≤ target, GLB ≤ 3MB, validator 0 errors, IoU vs gold)│
        → push ghcr.io/…/menu3d-worker                                      ─┘
```

- **100% self-hosted alternative:** Forgejo + Forgejo Actions (GitHub Actions-compatible YAML) or Woodpecker CI, with Harbor or the Forgejo registry.
- **Renovate** for dependency PRs. Conventional commits + changesets for versioning.
- **Rollback:** Coolify redeploys the previous image tag. DB migrations are forward-only and backward-compatible (expand → migrate → contract).

## Claude Code setup for this repo

`.mcp.json` (suggested):
```json
{
  "mcpServers": {
    "context7":        { "command": "npx", "args": ["-y", "@upstash/context7-mcp"] },
    "shadcn":          { "command": "npx", "args": ["shadcn@latest", "mcp"] },
    "playwright":      { "command": "npx", "args": ["-y", "@playwright/mcp@latest"] },
    "chrome-devtools": { "command": "npx", "args": ["-y", "chrome-devtools-mcp@latest"] },
    "postgres":        { "command": "uvx", "args": ["postgres-mcp", "--access-mode=restricted"],
                         "env": { "DATABASE_URI": "postgresql://app:app@localhost:5432/menu3d" } }
  }
}
```
Add Payload's `@payloadcms/plugin-mcp` to `payload.config.ts` to expose collections as MCP tools (seed demo menus from Claude). Use the already-installed **ui-ux-pro-max** skill to generate 4–6 restaurant theme presets (sushi-dark, trattoria-warm, café-minimal, parrilla-bold…) as token sets mapped to shadcn CSS variables.
